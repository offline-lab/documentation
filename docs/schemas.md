# Schemas

Machine-readable schemas for all Offline Lab data formats. Implementors of appctl,
buildctl, or compatible tooling should validate against these.

---

## Package formats

| Schema | Format | Description |
|---|---|---|
| [package-yaml.schema.json](schemas/package-yaml.schema.json) | JSON Schema | `package.yaml`: build-time package definition written by app authors |
| [package-metadata.schema.json](schemas/package-metadata.schema.json) | JSON Schema | `<name>_<version>_<arch>.json`: metadata generated by buildctl, shipped alongside the DDI (`.raw`) |

See [Package Format](specs/package-format.md) for the full field reference and examples.

---

## Repository formats

| Schema | Format | Description |
|---|---|---|
| [repo-index-root.schema.json](schemas/repo-index-root.schema.json) | JSON Schema | `repository.json`: discovery manifest declaring per-class URLs (bases/images) and signing keys. (Schema needs updating to reflect the merged model — see [Repository](specs/repository.md) for the current canonical shape.) |
| [repo-index-arch.schema.json](schemas/repo-index-arch.schema.json) | JSON Schema | `<class>/<arch>/index.json`: per-arch per-class index (apps or bases). (Schema needs updating to reflect the merged model — see [Repository](specs/repository.md) for the current canonical shape.) |

See [Repository](specs/repository.md) for the directory layout, signing model, and client flow. The markdown spec is the source of truth while the JSON Schema files are pending updates.

## On-device state

| Schema | Format | Description |
|---|---|---|
| [on-device-state.md](schemas/on-device-state.md) | Markdown + JSON examples | File-per-record JSON layout under `/var/lib/appctl/state/` (repos, packages, bases, images, locks). Replaces the earlier SQLite design. |

## Host resource baseline

| Schema | Format | Description |
|---|---|---|
| [resources.schema.json](schemas/resources.schema.json) | JSON Schema | `/var/lib/appctl/resources.json`: host resource baseline written at boot by `offlinelab-resources.service` |

See [Resource Tracking](specs/resource-tracking.md) for how appctl uses this file for pre-install capacity checks.
